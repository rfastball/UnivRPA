# 릴리스 이후 구조 검토 후속 수정

## 수정 순서

1. KEY와 COMBO의 공통 키 파서에서 숫자 VK는 1~254의 십진 정수 표기만 받는다. 키 이름과 영문 한 글자는 유지한다.
2. CALL 대상 LABEL의 종료점을 찾을 때 같은 깊이에서 형제 분기로 넘어가면 탐색을 끝낸다. 안쪽 조건의 조기 RETURN과 서브루틴 내부 점프 라벨은 유지한다.
3. 명령 등록 여부와 슬롯의 원문 검사를 실행기·편집기·실행 전 검증에서 공유한다. 건너뛴 분기의 변수나 픽셀 토큰은 해석하지 않는다.
4. 스크립트 원값, 표 헤더, 표 본문의 표시값 복원에서 같은 통화 정밀도 규칙을 사용한다. 날짜와 표 본문의 표시 형식은 보존한다.
5. 기존 테스트에 재현 사례를 넣어 수정 전후를 비교하고, 컴파일·전체 테스트·워크북과 소스 일치를 확인한다.

## 회귀 검증 계획

- 기존 입력 드라이버에서 소수 키 코드의 키 누름·해제가 0회인지 본다. 기존 구두점 검사와 같은 사례 표를 쓴다.
- ProgramImage에서 형제 분기의 RETURN 거부와 같은 분기의 RETURN 허용을 확인한다. 엔진의 기존 임시 시트에서 뒤쪽 행의 정적 오류가 앞줄의 입력을 막는지 확인한다.
- FOREACH_ROW 테스트의 기존 시트에 소수점 다섯째 자리 이후만 다른 통화 헤더 두 개를 놓고 각 열의 값을 구별해 읽는다.
- 공개 테스트, 테스트 파일, 전체 스위트당 Excel 실행 횟수는 늘리지 않는다. 기존 재귀 호출·날짜·좁은 열·동적 값 검사는 유지한다.

## 완료 및 검증

- 수정 전 전체 테스트는 17개 통과, 4개 실패였다. 잘못된 키 전송, 형제 분기의 RETURN 허용, 실행 전 오류 누락, 통화 헤더 충돌이 각각 기존 스위트에서 재현됐다.
- 수정 후 엔진 통합 테스트의 실패 단언은 0개였다. IF와 SELECT 양쪽의 분기 경계를 포함한 최종 전체 테스트는 21개 통과, 실패·건너뜀 0개였다.
- VBE 컴파일과 워크북 저장이 성공했다. 린트는 41개 파일에서 지적 0건이었고, 워크북 대조 결과는 `clean=true`였다. 프로젝트 잠금을 해제했다.
- 첫 반영 전 워크북 백업은 `20261118-000511-177-push`이다. 공개 테스트 수와 스위트당 외부 프로세스 수의 변화는 0이며, 키 입력은 가상 드라이버에서 검증했다.
